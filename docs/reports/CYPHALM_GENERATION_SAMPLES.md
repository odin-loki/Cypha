# CyphaLM generation samples (cold gate24, 2026-09-20)

Unprimed `CyphaLMModel` with production hp recipe (`table_bits=16`, vocab 256). No checkpoint loaded; outputs are **not** quality benchmarks — they document that decode paths run end-to-end on the bit-tree / serve API.

Host: cloud agent VM, `cyphalm_generate` built Release with g++.

**Superseded defaults (2026-09-23).** These samples predate the decode
changes in [`CYPHALM_LM_QUALITY_REPORT.md`](CYPHALM_LM_QUALITY_REPORT.md):
temperature 0.8, min-p 0.1, no learning from output, exact greedy, and word
lookahead (K 8) are now the defaults, and `cyphalm_generate --load` serves a
trained checkpoint or ensemble. Rerunning the commands below today gives
different output.

## CLI flags exercised

| Flag | Role |
|------|------|
| `--max-bytes` | Cap generated bytes (alias `--max-tokens`) |
| `--strategy` | `greedy`, `beam`, `top_p`, `temperature`, `top_k` |
| `--beam` | Beam width (`strategy=beam` defaults to 4 if unset) |
| `--top-p` | Nucleus mass for `top_p` |
| `--temperature` | Softmax temperature for sampling strategies |
| `--latency` | Print wall `latency_ms` for the full decode |

## Latency snapshot (greedy vs beam=4)

| Config | `max-bytes` | `latency_ms` |
|--------|-------------|--------------|
| greedy | 24 | 4962 |
| beam=4 | 16 | 14383 |

Beam search replays hypotheses on a single predictor snapshot and prunes to `min(vocab, max(2×beam, 16))` extensions per step — still ~2.9× slower than greedy here for fewer bytes, dominated by repeated bit-tree fan-out.
