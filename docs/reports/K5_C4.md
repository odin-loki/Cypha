# G3: K5 counts from clean C4 prose too

**Odin Loch** · registered 2026-11-12, before any arm runs · branch `wip/k5-c4` · GENERATION_PLAN §13.48 (W1b), §13.63 (HLT), §13.64 (C1); [K5_SCALE](K5_SCALE.md), [GEN_WEB](GEN_WEB.md), [GEN_FACTS](GEN_FACTS.md)

(The arms, the screen, the measures, the deciding rule and the predictions below were written and committed before any arm ran. Results are added under them.)

## Why

- Going from 7 MB to 337 MB of clean prose (§13.48, W1b) was the largest reading gain the project has measured: blind raters 0.940 against D0.
- J4 (§13.64) wrote C1: 1.50 GB of clean C4 web prose, 764,046 documents, one per line, with every GEN-A, GEN-W and SCRIBE span removed (`/mnt/d/cypha_llm/c4prose/c1_train.txt`). K5 has not read it.
- **Question:** does K5 read better when it also counts from some of C1?
- K5_SCALE read more text once before, judged only by SCRIBE; copy32 rose to 0.17–0.25. No reader has judged more text past 337 MB.

## The change: none in code

`--k5-more PATH` (`word_kn.hpp`) appends PATH to K5's text (`fuzzy/train.txt`, a newline, then PATH). The vocabulary, every word ID, the 256 exchange classes and K5's class model come from K5's own 7,053,155 bytes (§13.48 W1b), so the planner's skeletons and statistics keep working. Only the counts grow: K5's word counts, the gate's co-occurrence counts, and the 12-word cap's windows.

- An explicit `--k5-more` replaces the default one (`cyphalm_trie.cpp`: the default `train_all.txt` is used only when no `--k5-more` flag is given). It takes one file, so each arm gets one combined file.
- **Combined files** (`/mnt/d/cypha_llm/c4prose/k5c4_C{N}.txt`, not in git; written by a short script, sizes and sha256 in the results): `train_all.txt` (329.6 MB, K5_SCALE's clean enwik9), then the first N MB of `c1_train.txt`, cut at the end of the document that holds byte N.
- **The LDA term stays on `train_all.txt`.** `--k5-disc-text` defaults to the more-text, and the LDA model is cached for `train_all.txt`. Every arm passes `--k5-disc-text /mnt/d/cypha_llm/k5scale/clean/train_all.txt`, so the LDA model is HLT's own (loaded from the same cache) and only the counts change.

## Measures (dev)

- GEN-A dev: SCRIBE v2 with its 95% interval (score of record), v3.1 beside it, copy32 (against K5's whole text, as `sample` reports it), verbatim13.
- Fact precision: `python3 -I scripts/gen_fact_check.py run --v2 --out bench/k5_c4/facts HLT=… C150=… …` (GEN_FACTS amendment A1). Statements a sample, share contradicted, precision S/(S+C), with 95% intervals.
- GEN-W dev (`scripts/gen_eval_web.sh`, same flags), **report only**: SCRIBE v2 and v3.1, copy32. HLT is run on GEN-W too, as its baseline.
- K5's bits a byte on the human continuations (`k5_cont_bpb`), GEN-A and GEN-W.
- Peak RAM (`/usr/bin/time -v`, largest process), K5's build time (from `sample`'s log), wall time.
- Samples that differ from HLT, in all 250 and in the 50 rated prompts.

## The screen

**Reading.** For each arm I read the first 20 samples by prompt number that differ from HLT, on dev prompts the raters will not see (not in `bench/blind/llm_rating/prompts.json`), each beside HLT's. Strict: the arm passes only if, by my reading, it reads at least as well as HLT (grammar, sense, staying on the prompt's subject) and does not bring in web junk (adverts, calls to buy, lists of products, "click here" text, first-person shop talk).

**An arm passes if all hold:**
- verbatim13 is 0;
- copy32 at most 0.30;
- GEN-A dev SCRIBE v2 at least HLT's − 0.03;
- fact precision at least HLT's − 0.05;
- my reading.

**Candidates:** at most 2 that pass. If all three pass: the largest arm, and of the other two the one with the higher GEN-A SCRIBE v2. If none passes, nothing goes to the raters, and I say why.

## The deciding judge

`python scripts/blind_rate.py make --out bench/blind/c4_pair --ids bench/blind/llm_rating/prompts.json --arm HLT=… --arm X=… [--arm Y=…] --mode pair --baseline HLT --seed 20261126`: the 50 rated prompts, cut at 460 characters, four fresh blind Claude raters, each candidate against HLT. Packets, `key.b64`, `RATER_PROMPT.md`, the GEN files and summaries are committed and pushed before the raters run. `KEY.json` stays out of the repo. The lead runs the raters.

**The rule (§13.38):** an arm reads better than HLT if its win share minus 0.5 is above 0, its 95% bootstrap interval excludes 0, and both rater pairs agree on the sign. If both candidates read better, the one with the higher win share; on a tie, the higher lower bound, then the lower copy32 (§13.51's tie rule). Only the adopted arm's GEN-A test is read, once. Odin decides the default (the cost in RAM is his call).
