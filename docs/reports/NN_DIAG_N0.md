# N0: the neural diagnostic (similarity or state?)

**Odin Loch** · 2026-11-01 · [GENERATION_PLAN](../GENERATION_PLAN.md) §13.3 and §13.5 · branch `wip/nn-diag`

(A draft written by `bench/nn_diag/run_n0.sh` at the end of the run. The setup and predictions were registered in §13 before any run.)

**Question.** Fuzzy matching has two parts: similarity (what counts as alike) and a state that carries the whole past. Which part buys more text quality? N0 trains two small neural models as instruments, beside two count models, on the same text, tokens and decoder, and scores their samples with SCRIBE.

**The instruments.** The neural models are never part of CyphaLM, never a default, and their text is never training text. They are deleted or archived after this report. Q0 (Qwen 3.5 9B) is a yardstick only (§13.5).

## Setup

- **Text (W1).** enwik9 bytes [100,000,000, 1,000,000,000), cleaned by `scribe docs`, one page per line. Pages holding any 32-byte span of a GEN-A dev continuation are dropped. Train is the first 128 MiB of what is left; val is the next 4 MiB.
- **Tokens.** One BPE vocabulary with word boundaries (GPT-style pretokens), 8,192 tokens, learned by `cyphalm_tok train` on train. Every arm uses it.
- **Arms.**
  - K5, K8: interpolated modified Kneser–Ney, orders 5 and 8 (TOK-A's `KneserNey`, T4c's model: no ∞-gram).
  - M5: a feedforward net over 4 tokens (embeddings 256, hidden 1,024 with tanh, softmax over 8,192).
  - TR: a transformer, 6 layers, d 384, 6 heads, pre-LN, tied embeddings, learned positions, context 256.
  - M5 and TR: two passes over train (each target token seen twice), AdamW (β 0.9, 0.95), linear warm-up then cosine to 10% of the peak rate, gradient clip 1. The best checkpoint by val loss is kept (24 checks).
  - Q0: Qwen 3.5 9B (Ollama, raw completion, no template, thinking off).
- **Decoding, the same for K5, K8, M5 and TR.** T4c's rule, from `sample_t4b` in `cyphalm_tok_gen`: the repeat ban (a token is banned if any of its bytes would follow an 11-byte window with the byte that followed it earlier in the text; if every token is banned, none is), then q^(1/T), then the smallest set of tokens holding 0.9 of the mass, then one draw. T 0.8 and 1.0. 250 GEN-A dev prompts, 600 bytes, seeds 1000003 (k + 1) + 7919 t. One C++ decoder (`cyphalm_tok_gen n0-gen`) serves every arm: Kneser–Ney in process, the nets over a pipe. Q0 uses Ollama's own nucleus 0.9 (top_k 0, no repeat penalty), cut at 600 bytes.
- **Measures.** SCRIBE v2 by `gen_eval.sh`'s ladder (pack enwik8 [16, 48) MiB, reference [48, 56), test [56, 64), vectors v32, seed 20261027), pooled and per temperature with 95% intervals, and its axes. Copy share: generated bytes inside a 32-byte span of the 128 MiB train. The 12-word cap: the share of samples holding a run of 13 or more whitespace words found verbatim in train. Invented words: letter runs (lower case) that never occur in train. Bits per byte on val and on the GEN-A dev continuations.
- **Δsim = M5 − K5, Δstate = TR − M5**, on pooled dev SCRIBE, each with a paired bootstrap over prompts (2,000 draws). A diagnostic, not a gate.

## Changes from the registration

1. **Decoding over canonical tokens, without the bridge.** T4c heals the prompt through TOK-A's exact byte–token bridge, which needs an exact byte marginal; a neural arm has none. So every arm encodes the prompt as the tokenizer encodes training text and draws from there. The draw itself (repeat ban, temperature, nucleus, seeds) is T4c's code, copied line for line into `n0_sample`. One decoder serves all arms, so the decoding is identical.
2. **Continuation bits.** Scored on the canonical tokens of prompt + " " + continuation after their longest common prefix with the prompt's tokens. Bytes are the bytes those tokens cover (a few prompt bytes when the last prompt token merges with the continuation). The same for every arm.
3. **Val bits per byte.** The val text as one token stream; token 0 is skipped by every arm. K5 and K8 use their whole history; M5 its 4 tokens; TR windows of 256 at stride 128 (each token scored once, with at least 128 tokens of context after the first window).
4. **The page filter uses the dev continuations only.** The task rules forbid reading `gen_prompts_test.tsv`. The test continuations lie in enwik8 [72, 95.37) MiB, outside W1 by construction (§13.3), and N0 never reads the test split.
5. **Train and val end at a page end** (the last newline before 128 MiB and before the next 4 MiB).
6. **Build.** The tools are built with `g++ -O3 -march=native` (as `scripts/build_1tb_tools.sh` builds its tools), not CMake: the full CMake project builds hundreds of targets N0 does not use.
7. **Threads.** Torch uses 32 threads, one per physical core. With 64 (hyperthreads) one training step was 1.6 to 2.3 times slower (measured before the run). The C++ steps use 64.
8. **Tool changes.** `cyphalm_tok train --bytes N` (learn on a file's first N bytes, not enwik8's first 7 MiB); `cyphalm_tok_gen n0-encode | n0-score | n0-gen` (new); `scribe ladder --export` names each trie-rung text by its GEN line (`LABEL/trie/gN`), so scores pair by prompt. Nothing else in the tools changes; their selftests pass.
9. **Q0's sampler** is Ollama's (nucleus 0.9, no repeat ban), not T4c's: Ollama has no repeat ban. Qwen has likely read these Wikipedia pages (modern versions), so Q0 is a reference point, not a fair comparison, and its copy share against our train does not measure its memory.

