## The Omega encoder

The header states the supersession outright — this is the strongest ordering edge in the
archive (see [`../TIMELINE.md`](../TIMELINE.md#two-architectural-families)):

> Replaces BinaryEncoder with OmegaEncoder implementing the five-operator Omega information
> field formula proven in Phase 8 neural network verification.

For a real signal `x ∈ ℝⁿ`:

```
Ω(x) = concat[ M(x), M(D(x)), M(D²(x)), R(x,K), A(x,L) ]

  M(x)   = [μ, σ, κ, γ]            mean, std, EXCESS kurtosis, skewness (single pass)
  D(x)   = x[i+1] − x[i]           first difference;  D²  = D(D(x))
  R(x,K) = L1-normalised |rfft(x)| reduced into K = 16 bands via np.add.reduceat
  A(x,L) = autocorrelation at L = 8 log-spaced lags, on the mean-centred signal
```

applied at three temporal scales — full, first half, second half — giving
3 × (4+4+4+16+8) = **108 named scalars**, plus a 256-bin byte histogram and 6
token-structure dims.

`κ(D(x))` is singled out as the dominant discriminator, annotated as "a linear encoding of
the string attractor density γ*/n (empirical r = 0.9985)" (`Cypha.py:256-258`).

Features reach the vector by **numeric-direct hash embedding** — `v[|hash(name)| mod d] +=
value`, then L2-normalise — presented as a deliberate stance: no learned projection, metric
structure preserved, instantly extensible to new domains.

### Two modality rescues

Pure Omega on raw bytes collapsed on signal data (cross-class cosine similarity ≈ 0.99), so
v5 adds two domain-specific paths:

- **`_encode_iq`** (`:405-560`) — rotation-invariant by construction: geometric-spaced PSD
  bands, spectral centroid / bandwidth / entropy / peak, envelope moments and normalised
  variance, instantaneous frequency, differential-phase statistics including the coherent
  order `|E[e^{j2Δφ}]|`, power-normalised cumulants `C20`, `C40`, `C42`, and a four-quadrant
  PSD asymmetry feature for USB.
- **`_encode_audio`** (`:562-748`) — a 26-band mel filterbank,
  `mel(f) = 2595·log₁₀(1 + f/700)`, over 80–4000 Hz at an assumed 16 kHz, across four
  temporal segments, scaled by `MEL_SCALE = 20.0`.

These are the first admissions in the archive that one universal encoder is not enough.

## The data pipeline

`download.py` → `convert.py` → `benchmark.py`, all three **resumable state machines** over a
JSON file with identical `load_state` / `save_state` / `mark_completed` / `mark_failed`
helper sets. Everything meets at one line format, `INPUT|||LABEL`, with four prefixes
selecting an encoder path: none (text), `iq:` (hex int8 interleaved), `pcm:` (hex int16),
`arr:` (base64 float32).

The substrate that makes it scale is **byte-offset streaming**: `_build_offset_index`
(`:3252-3266`) scans a file once and returns an `int64` array of the offset of every line
containing `|||`; training shuffles the *offset array*, not the data, and seeks per sample.
Dataset size becomes independent of RAM.

`CyphaStateful` adds per-dataset epoch checkpointing with compressed `.npz` anchor archives,
atomic temp-rename writes, old-epoch pruning, and full index rebuild on resume.

`AnchorMemory` is rebuilt from v4's 60-line dict into a real prototype store: BLAS `_V @ q`
matmul lookup, dedup-on-store with EMA centroid refinement, LVQ2.1 boundary sharpening at
η = 0.02, closest-pair eviction, greedy-pivot consolidation, and per-class adaptive caps
derived from TwoNN intrinsic dimensionality and the Gram spectral gap.

## The self-audit

This is the most important thing in v5, and arguably in the archive.

HLFC compression is not quietly dropped. It is removed with a tombstone and a profiled
justification:

```python
# [HLFC compression removed: see audit 2025-02 — orphaned output, 45% hot-path overhead]
```
— `Cypha.py:840`

```python
# HLFC.compress() removed from hot path (profiled 2025-02):
#   output was never consumed by train_step() or infer()
#   cost: 0.254ms/call = 45% overhead, ~50s wasted per 100k-sample epoch
#   reconstruction cos_sim = 0.48 (lossy on sparse Omega vectors)
#   HLFC.compress() remains available as a standalone utility for
#   signal-domain data (IQ/audio); do not call on text/Omega encodings
```
— `Cypha.py:2373-2379`

That is the project diagnosing, quantifying and fixing the exact pathology that
[v2](02-v2.md#the-compression-layer-is-computed-and-thrown-away) and
[v3](03-v3.md#the-core-is-computed-and-discarded) had carried: a subsystem computed on the
hot path whose output nothing reads. Someone profiled it, measured the waste at 45% and
~50 seconds per 100k-sample epoch, checked the reconstruction quality (cos_sim 0.48), and
deleted it with a note explaining why.

Four versions of the compression machinery — `HLFCCompressor`, `FundamentalExtraction`,
`SymmetryEncoding`, `CrystalLatticeMapping`, `DNAFolding` — end here.

### The audit is dated 2025-02, and that is a typo

Five comments in `Cypha.py` cite a `2025-02` audit (`:840`, `:1284`, `:1375`, `:1732`,
`:2373`). A year earlier than everything around them, it is worth resolving, because these are
the only self-dated claims in the archive.

They cannot be from February 2025. The audit profiles `HLFC.compress()` **against Omega
encodings** — "lossy on sparse Omega vectors", "do not call on text/Omega encodings" — and the
string `Omega` does not occur even once in either directory that carries a 2025 date:

| Directory | date | occurrences of `Omega` |
|---|---|---:|
| `prototypes/` | 2025-02-26 | **0** |
| `cypha-v1/` | 2025-03-04 | **0** |
| `cypha-v5/` | 2026-02-21 | 112 |

An audit cannot measure reconstruction loss on a representation that will not exist for
another year. Read as **2026-02**, the comments sit in the same month as v5's own
documentation, and the tombstone becomes contemporaneous with the code holding it. The
identical block appears verbatim in v6 and v7, carried forward by copy — one authoring event,
propagated, not three independent audits.

### And yet the larger instance survives

The same version still stores and looks up on `encode_features(text)` — the raw Omega vector
— while `forward()`'s output goes only to `MetaLearning.loss` and verbose printing
(`:2486`, `:2594`). Classification remains mathematically independent of `ResonanceField`,
`ResonatorLevel`, `AssemblyLevel`, `ModuleLevel` and `GlobalLevel`.

v5 found the 0.254 ms/call orphan and removed it. It did not remove the orphan that is the
entire architecture. The README's §8.1 step list actually describes the real data flow
correctly, contradicting its own §2 and §5.3.

## A serious latent bug: the hash embedding is not stable across processes

`abs(hash(name)) % output_dim` on a Python `str` is salted by `PYTHONHASHSEED`, which has
been random per process since Python 3.3. The documentation states the opposite:

> The hash function is deterministic: the same feature name always maps to the same index.
> — `../archive/cypha-v5/README_Cypha.md:66`

It is deterministic *within* a process. Across processes it is not:

```console
$ for i in 1 2 3; do PYTHONHASHSEED=$i python3 -c "print([abs(hash(n))%4096 for n in
      ['omega_full_mean','omega_d1_kurt','band_07','lag_3']])"; done
[2558, 3495, 854, 2128]
[2556, 3467, 1664, 1706]
[178, 407, 2921, 1639]

$ # default (random) seed, three separate processes
[602, 1522, 1760, 2148]
[3988, 784, 2169, 2119]
[2941, 4037, 2133, 894]
```

Every feature lands in a different coordinate in every run. Since `CyphaStateful` persists
anchors as vectors laid out under one process's salt, a checkpoint resumed in a new process
encodes its queries in an **incompatible coordinate system**. The documented resume path
(`benchmark.py:126-134`) would be comparing vectors that no longer share a basis, which
would silently invalidate any accuracy figure obtained after a resume.

The mechanism is plainly visible at `Cypha.py:168` and `:313`. Whether any reported number
was actually affected cannot be determined from the archive, because no run logs survive.

## Dead code

- `EncoderParams` / `AdaptiveControlLoop` — `p` is threaded through every `OmegaEncoder`
  public method and never read. The loss → control-loop → encoder-parameter path is a closed
  loop with no output, now in its third version.
- `GAIN_A = 0.04` (`:42`) — defined, never referenced.
- `SparseComputer`, `WorkStealer`, `PrecisionController` — instantiated at `:2326-2328`,
  never called.
- `EventScheduler.schedule()` and `ResonanceField.queue_event` — never called, so `pop_due()`
  always returns `[]`.
- `Cypha.infer_top_k` (`:2658-2663`) — computes a bridge result, discards it, then passes an
  **undefined name** `state` to `memory.lookup`. Raises `NameError` on any call.
- `Cypha.train_file` is defined twice in the same class, at `:2543` and `:2666`; the second
  silently shadows the first.

## How to read this era

v5 is the archive's most professional version and its most self-contradictory. The
engineering is real: streaming over byte offsets, atomic checkpointing, LVQ2.1 boundary
sharpening, intrinsic-dimensionality-derived caps, rotation-invariant IQ features, a mel
filterbank, and a resumable pipeline over ten public datasets. The self-audit that killed
HLFC is the kind of thing a healthy project does.

At the same time the documentation describes a system that is not the one shipped, a
`NameError` sits in a public method, `train_file` is defined twice, and the encoder's index
assignment is not reproducible across processes.

The pattern to carry forward: **v5 proved the project could find and remove dead
machinery.** The fact that it removed the 0.254 ms orphan and kept the architectural one is
the clearest signal available of why v8 eventually restarted from nothing.
