# cypha_accel — Fused GPU / CPU Acceleration Kernels

`cypha_accel` provides drop-in replacements for the NumPy hot paths in `Cypha.py`. When **CuPy** is available and a CUDA device is visible, computation runs on GPU; otherwise it falls back to NumPy with no behaviour change.

`Cypha.py` imports from `cypha_accel` automatically — no manual wiring is needed.

---

## What it accelerates

| Export | Module | Role in `Cypha.py` |
|--------|--------|---------------------|
| `fused_score_llr` | `score_batch.py` | Fused `(H-μ₀)⊙inv_v`, `R @ D.T`, MDL bias — the **LLR core** of `score_matrix` and `generate` |
| `project_features` | `score_batch.py` | Batched encoder projection (`batch_encode`) |
| `softmax_rows_llr` | `score_batch.py` | Row-wise softmax over LLR matrix |
| `fused_features_to_latent_and_llr` | `score_batch.py` | End-to-end encode+score for CPU path |
| `fused_features_to_device_latent_llr` | `score_batch.py` | End-to-end encode+score, keeps tensors on GPU device |
| `fused_batch_infer_indices_confs_cupy` | `score_batch.py` | Full batch inference returning `(label_indices, confidences)` on CuPy array |
| `cross_r_dT` | `cross_gemm.py` | Batched `R @ D.T` GEMM — used by `score_matrix` in non-fused fallback |
| `cuda_gemm_usable`, `warmup_cuda` | `cuda_util.py` | CuPy availability check and GPU warmup |
| `cupy_gemm_burn` | `gpu_stress.py` | GPU stress test for tuning and benchmarking |

**Not in `__init__` but used internally:** `nig_gh.py` — vectorised GH–NIG `gig_e_inv_v_vec` / `nig_r_eff_vec`, tested in `tests/test_gig_vectorized.py`. Depends on `bessel_ratios.npz` at repo root (generated by `python scripts/export_bessel_ratios_npz.py`).

---

## Runtime behaviour

- **GPU (CuPy):** used automatically when `cypha_accel.cuda_util.cuda_gemm_usable()` returns `True`. No configuration needed.
- **CPU (NumPy):** fallback when CuPy is absent or no CUDA device is visible.
- **Mixed precision:** set `CYPHA_ACCEL_FP32=1` to use fp32 CuPy matmuls instead of fp64 (useful for tuning throughput on consumer GPUs; slight numerical difference from the float64 reference).

## Install

CuPy is optional:

```bash
# CPU-only (default):
pip install -e .

# With CUDA 12.x:
pip install cupy-cuda12x

# With CUDA 11.x:
pip install cupy-cuda11x
```

---

## Tests

```bash
pytest tests/test_accel_cypha_wired.py tests/test_accel_cross_gemm.py tests/test_gig_vectorized.py -v
```

These test numerics against the float64 reference formula and cross-check the GPU/CPU fallback logic.

---

## GPU benchmarks

```bash
python scripts/gpu_microbench.py    # CuPy vs NumPy micro timing
python scripts/gpu_fullbench.py     # full pipeline timing
python scripts/bench_gpu_production.py  # combined bench + tuning bundle
```

Results are written to `artifacts/bench/`. See [`docs/benchmarks/BENCHMARK_GPU.md`](../docs/benchmarks/BENCHMARK_GPU.md) for a reference run.

## Parity with native C++

The fused LLR computation in `score_batch.py` is the Python-side reference for the native `cypha_parity` C++ tool. Numerics must match within float64 tolerance. See [`docs/port/PORT_CONTRACT.md §1`](../docs/port/PORT_CONTRACT.md) for the full contract.
