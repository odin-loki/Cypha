# v6 — the measurement era, and a missing engine

**Directory:** [`../archive/cypha-v6/`](../archive/cypha-v6/) · **mtime** 2026-02-27 ·
**11 Python files, 11,326 lines** · 4.3 MB including `Profiling/`

The largest and most instrumented tree in the archive. v6 is where Cypha stopped asserting
things about itself and started measuring them — four profilers, two game benchmarks, a
multimodal profiler, and a formal mathematics document. Almost everything it measured came
back negative, and the code records the verdicts.

## The engine

`Cypha.py` is the Omega-2 engine, structurally v5's. Default `feature_dim=512`,
`resonance_dim=256`, `N_BANDS=16`, `N_LAGS=8`.

The encoder is the only path that affects classification:

- `_omega_at_scale` emits 36 named scalars — `_moments4(x)`, `_moments4(diff(x))`,
  `_moments4(diff²(x))` (12), 16 spectral bands via `np.add.reduceat`, 8 log-spaced
  autocorrelation lags — applied at three scales for 108 features.
- `encode_text` adds 256 byte-unigram frequencies and 6 token-structure scalars, then blends
  0.80 × Omega + 0.20 × a 128-bin bigram histogram.
- `_encode_iq` is a purpose-built automatic-modulation-classification front end, explicitly
  motivated by a measured failure: raw-byte Omega gave cross-class cosine **0.992** and 16%
  accuracy on 6-class RF.
- `_encode_audio` is a 26-band mel filterbank with an explicit design rule — *do not run
  Omega statistics on the mel vector*, because Omega destroys which-band-has-energy
  information — and `MEL_SCALE = 20` so five scalar features cannot dominate 78 mel features
  under unit norm.

Genuinely good work also appears in the memory: **adaptive per-class anchor capacity** derived
from measured boundary complexity (mean pairwise cosine spread, TwoNN intrinsic
dimensionality, Gram spectral gap) instead of a global ceiling, and **LVQ2.1 boundary
sharpening** applied online at every store.

### A measured cost of the hashing stance

`OmegaEncoder(output_dim=512)` precomputes **372** feature names and hashes them into 512
bins. Measured in one process: **256 distinct bins, 116 collisions** — roughly a third of the
vocabulary lands on top of another feature before any data is seen. The uniform-hashing
expectation for 372 names in 512 bins is 264.6 distinct bins (~107 collisions), so the
observed figure is ordinary collision behaviour rather than a pathological hash.

The exact count is **not reproducible**, because `abs(hash(name))` is salted per process — a
second measurement of the same encoder gave 258 distinct bins and 114 collisions. The name
count of 372 is stable; which names share a bin is not. That is the same defect documented at
[`05-v5.md`](05-v5.md#a-serious-latent-bug-the-hash-embedding-is-not-stable-across-processes),
and here it means the encoder's feature-collision structure — and therefore which features are
confusable — differs between every run.

### The architecture is still disconnected — now provably

v3's pathology persists, and v6 makes it dimensionally impossible to miss: `forward()`
returns a state in `resonance_dim` space (64 or 256) while `AnchorMemory` lives in
`feature_dim` space (512). **The two are never compared because they cannot be.** The
shipped classifier is a 1-nearest-prototype cosine lookup over hashed Omega features.

Three further mechanisms are dead at inference:

| Mechanism | Why it never runs |
|---|---|
| the k=15 class-normalised vote | `k_lookup = 1` at `:2887`, twelve lines after a docstring describing the vote as "FIX B1" |
| `ThoughtProcessor.deliberate` (Rocchio, LVQ2.1 window, anchor-density guard, confusion memory) | `k_lookup=1` means one candidate, so it returns at its `len(candidates) < 2` guard. Measured: 20/20 inference calls entered, **0 fired** |
| `EncoderParams` / `AdaptiveControlLoop` | updated every step, serialised into every checkpoint, printed in the epoch banner — and read by no encoder. Verified: encoding identical for `chunk_k=4` vs `99` |

## The verdict written into the code

This is the most important line in v6, and it closes the adaptivity thread:

```python
# Fixed α=0.05 — profiling (phases 3-10) shows ThoughtProcessor.suggested_alpha
# is counter-productive in every modality: chronic uncertainty overestimation
# during centroid migration drives overshoot. Fixed 0.05 outperforms adaptive
# by 10-19 percentage points. Confusion tracking above is preserved.
self.memory.store(inp, anchor_vec, out, ema_alpha=0.05)
```
— `Cypha.py:2503-2507`

The profilers ran, adaptive lost, and the constant was nailed down *with the reason recorded
in the source*. `suggested_alpha` is still computed on every step; it is simply not used.

The comment's core claim holds exactly — recomputing the nine cells from
`profiler3_alpha_report.txt`, fixed α = 0.05 beats `Adaptive (TP)` in **9 of 9**:

| | n/class 50 | 200 | 500 |
|---|---|---|---|
| text | 0.990 vs 0.863 → **12.7 pp** | 0.995 vs 0.895 → **10.0 pp** | 0.998 vs 0.875 → **12.3 pp** |
| audio | 0.885 vs 0.833 → **5.2 pp** | 0.892 vs 0.797 → **9.5 pp** | 0.857 vs 0.750 → **10.7 pp** |
| structured | 0.653 vs 0.425 → **22.8 pp** | 0.658 vs 0.488 → **17.0 pp** | 0.655 vs 0.462 → **19.3 pp** |

The stated range is the one detail that is off: the measured gaps run **5.2 to 22.8 pp**, not
10 to 19. "Counter-productive in every modality" is exactly right; the magnitudes were quoted
from memory.

## The four profilers

[`../archive/cypha-v6/Profiling/`](../archive/cypha-v6/Profiling/) — four experiments, four
reports, 3.3 MB of JSON results. All four came back negative.

### Profiler 3 — adaptive α loses everywhere

| Modality | n/class | Winner | `Fixed α=0.05` | `Adaptive (TP)` |
|---|---|---|---|---|
| text | 50 | Fixed α=0.05 (0.990) | **1st** | 8th / 9 |
| text | 200 | Switch adaptive→0.05 (0.998) | 2nd | 7th / 9 |
| text | 500 | Fixed α=0.05 (0.998) | **1st** | 6th / 9 |
| audio | 50 | Anneal 0.40→0.05 (0.905) | 2nd | 7th / 9 |
| audio | 200 | Fixed α=0.05 (0.892) | **1st** | 6th / 9 |
| audio | 500 | Fixed α=0.15 (0.877) | 4th | 9th / 9 |
| structured | 50 | Fixed α=0.05 (0.653) | **1st** | 8th / 9 |
| structured | 200 | Fixed α=0.05 (0.658) | **1st** | 6th / 9 |
| structured | 500 | Fixed α=0.05 (0.655) | **1st** | 7th / 36 |

Adaptive is never better than sixth. The report states its own decision rule:

> If fixed_low always wins → adaptive mechanism should be disabled entirely.

It did, and it was — see the code comment above.

### Profiler 2 — the adaptation path never fires

For every distribution shift in {0.1, 0.2, 0.3, 0.5, 0.7}, the best-threshold row reads
`writes=0`, `write_acc=0.000`, `recovery=+0.000`, `forgetting=+0.000`, `net_gain=+0.000`.
A confidence threshold of 1.5 gates out 100% of writes. The underlying degradation is real
though: from base accuracy 0.847 on text, a shift of 0.3 costs 22.4%, 0.5 costs 52.0%, and
0.7 costs 73.6%.

### Profiler 4 — the detector gets worse with more evidence

| Detection step | Overall accuracy | Type A F1 | Type B F1 | Type C F1 |
|---|---|---|---|---|
| 6 | 0.333 | 0.29 | 0.48 | **0.00** |
| 10 | 0.200 | 0.24 | 0.24 | **0.00** |
| 20 | 0.167 | 0.33 | 0.00 | **0.00** |
| 30 | 0.167 | 0.33 | 0.00 | **0.00** |
| 50 | 0.167 | 0.32 | 0.00 | **0.00** |

More evidence makes it worse. Type C is never detected at any step. The detector converges
on predicting Type A for everything (recall 1.00, precision 0.19).

The taxonomy it defines (`cypha_profiler4_archetype.py:41-43`) outlives the detector —
it is the vocabulary the later 27,524-run sweep uses, where **every single record** comes
back as a Type-C subtype. See
[`../SWEEP_ANALYSIS.md`](../SWEEP_ANALYSIS.md#the-archetype-labels-are-worse-news-than-they-look).

### Profiler 1 — transition scaling

Detects a transition in margin-σ as examples per class scale, per modality, reporting
`improving` / `degrading` / `no_transition`. Audio shows `no_transition` at 50, 200, 500 and
1000 examples per class. The report's own rule:

> If no transition detected at any budget: → Modality is Type C (encoder-limited). No
> stopping criterion applies. Flag as "encoder mismatch" and halt training early.

## The game benchmarks

Two harnesses, and they are very different in kind.

**`game_live_benchmark.py`** is the real one. It contains a rules-correct pure-Python 9×9 Go
engine in ~110 lines — capture, ko-point detection, suicide prohibition, superko history,
Chinese area scoring with komi — and behaviourally clones Stockfish, `treys`
Monte-Carlo GTO poker and greedy Go self-play, then plays the trained model against
Stockfish at depth 20, a rule-based poker bot and a greedy Go bot. Its Go credit assignment
is finer than its own README describes: a winner's move is only labelled `best_move` if the
winner's territory lead actually increased on that move.

**`game_benchmark.py`** is an instrument rather than a benchmark. Its stated goal is not
accuracy but forcing a target operating regime — "hippo_hit_rate target ~35-55%",
"deliberation_rate target ~35-55%" — so the deliberation pipeline can be profiled under load
instead of being bypassed by easy data. It engineers decision-boundary ambiguity through a
`BOUNDARY_PAIRS` map and a 25% boundary-example rate, and installs an 82-column profiler
entirely by monkey-patching module functions and bound methods with `functools.wraps`.

Two honest caveats belong with it. First, the README states plainly that "the evaluation set
is not truly held-out in the machine learning sense — it is a live learning phase", because
`give_feedback` is called on every test example. Second, several header claims do not match
the code: the advertised "piece-square table evaluator" never constructs a board and never
reads its PSTs; the "500-iter Monte Carlo equity engine" (`_mc_equity`) draws no cards and
runs no iterations, adding `N(0,5)` to a class-conditional hint; "20 openings" is 16;
"15 piece configuration types" is 12; and the claimed 55–70 tokens per example counts closer
to 32–48.

## The Math Proving document

`Cypha Encoder Math Proving.md` (351 lines, 11 sections, 18 references) is the archive's most
formal document and its least verifiable.

| Claim | Problem |
|---|---|
| "computed in O(n) time and O(1) space (for online updates)" (`:110`) | the implementation is `O(n log n)` — three FFT calls per scale, plus full FFTs in the IQ and audio paths — and `O(n)` space. The §5.2 semiring merge formulas that would make online updates possible are **never implemented**; no merge function exists in the file. |
| "Pearson correlation r = −0.9985" (`:103`) | restated at `Cypha.py:105` as "r=0.9985 with γ*/n" — sign flipped, referent changed from LZ density to attractor density. Theorem 4.1's own form `κ ≈ A(1−δ)/δ + B` is **hyperbolic, not linear**, so an r of 0.9985 against δ is not consistent with the theorem as stated. |
| §7 in its entirety — a CNN experiment (16 conv filters, GAP, 32-unit hidden ReLU, 7-class softmax, 5 epochs, SNR 10–20 dB), a linear encoding law ‖h‖ = 0.603·κ(D(amp)) + 1.750 with r=0.938 p=0.0018, a 21/32 hidden-unit operator census, an 8/8 primitive/composite filter split, a conjugate compression law, and 26/210 ultrametric violations | **no training code, no saved activations, no analysis script exists anywhere in the archive.** None of it is reproducible from what survives. |
| "A single kNN-5 classifier on Omega features achieves 97.7% mean accuracy across all domains" (`:284`) | the shipped classifier is **1-NN** (`Cypha.py:2887`), and no benchmark output reproducing the figures is in the archive |
| §5.3: "2D images: D(x) = [gradient_x, gradient_y]", "Video: D(x) = frame_difference" | images and video reach the encoder via `arr:` → `encode_array` → `_encode_signal`, which **ravels to 1-D** and applies `np.diff`. No 2-D gradient operator exists. The profiler's video frame-differencing is done by the *data generator*, so its video scores measure a pre-digested feature vector, not the encoder. |
| `:237`: "The existing Cypha text encoder uses character trigrams — a fixed-lag-3 autocorrelation" | v6 uses byte **bigrams** at 20% weight, and hashed n-gram counting is not an autocorrelation in any formal sense |

The document is worth reading for its ambition — it is a serious attempt to give the Omega
encoder a theoretical basis. But its headline empirical results rest on artifacts that were
not preserved, and its central theorem does not have the functional form its correlation
claims require.

## The missing engine

**`archive/cypha-v6/Cypha.py` is not the engine v6's own files were written against.**

`game_benchmark.py` opens with

```python
from Cypha import (CyphaStateful, _build_offset_index, _read_at_offset,
                   deliberate_iterative as _orig_delib,
                   pnq_lookup           as _orig_pnq,
                   mcts_search          as _orig_mcts,
                   gria_cascade         as _orig_gria)
```
— `game_benchmark.py:54-58`

Four of those seven names do not exist in the `Cypha.py` beside it. The harness cannot
import. And the four are absent from **every** archived monolith:

| `Cypha.py` in | `gria` | `pnq` | `mcts` | `deliberate_iterative` |
|---|---|---|---|---|
| v5, v6, v7, v8, root | 0 | 0 | 0 | 0 |

Meanwhile `Cypha_README.md`, in the same directory, mentions **gria 14 times, hippo 25,
pnq 8, mcts 8, rocchio 5, reflexion 2, platt 2**.

So v6 holds three mutually inconsistent things: an engine that is essentially v5's code, a
README describing a far more elaborate one — ensemble deliberator (Rocchio + MCTS + PNQ +
GRIA), hippocampal memory, reflexion, Platt calibration — and a benchmark harness written
against *that* engine. **The engine the README documents was never archived.**

This matters beyond bookkeeping. `GRIA` — "Graded Reversible-Irreversible Algebra", a grade
parameter α ∈ [0,1] interpolating between reversible and irreversible operation — ships in
the native product today as `GRIAController`, `gria_lowrank.cpp` and
`gria_projection_alpha`, and names the living default **Hybrid GRIA+LSTM L2+Wave2 BPTT**. It
was implemented in the missing engine. See
[`../LINEAGE.md`](../LINEAGE.md#7-gria--the-one-family-a-idea-that-came-back).

## How to read this era

v6 is the version that grew up. The measurement infrastructure is real and the results are
believed: adaptive α was tested against fixed constants across three modalities and three
budgets, lost every time, and the loss was written into the source with its magnitude. That
is the behaviour of a project that trusts its instruments.

The same version ships an engine whose entire dynamical half cannot be compared to its
classifier because they live in different-dimensional spaces, a deliberation ensemble that
fires zero times in twenty inference calls, and a mathematics document whose headline
experiments left no reproducible trace.

Both halves are v6. The measurement culture is what reaches the native product — the
regression pins, the golden fixtures, the profile-guided defaults. The engine did not.
