## `Cypha.py` does not run

This is the central fact about v2, and it should be established before anything else.

```console
$ python3 -c "import ast; ast.parse(open('cypha-v2/Cypha.py').read())"
SyntaxError: line 1 — unexpected indent
  >>     print(f"Processing completed in {result['processing_time']:.4f} seconds")
```

The file begins on an indented line, in the middle of a demo function body. It was
assembled by concatenating chat-generated chunks **in the wrong order**: the ten section
banners appear in the sequence

```
line 1558  # 10. Speed Enhancement Layer
line 3992  # 9.  Meta-Learning & Optimization Layer
line 4419  # 8.  Thought Process Layer
line 6128  # 5.  Recursive Processing Layer
line 6591  # 6.  Feedback Control Layer
line 6948  # 7.  Multi-Level Processing System
line 7004  # 1.  Universal Encoding & Precision Layer
line 7252  # 2.  Harmonic Lattice-Folded Compression Layer
line 8140  # 3.  Resonance Field Layer
line 8664  # 4.  Event-Driven Processing Layer
```

— 10, 9, 8, 5, 6, 7, 1, 2, 3, 4 — with the module docstring and `ray.init()` stranded at
lines 6964 and 6993.

**Every other monolith in the archive parses cleanly**: v3, v4, v5, v6, v7, v8 and the root
monolith all pass `ast.parse`. v2 is the only one that does not. The largest implementation
in the project's history was never executable in the form that survives.

That reframes everything the v2 documents claim. They describe a system that was specified
in detail, transcribed into code shape, and — at least in this artifact — never run.

### What is dead even if you repair the syntax

Nineteen of the forty instantiated subsystems are never invoked. The entire **§5 Recursive
Processing Layer** and the entire **§6 Feedback Control Layer** are dead at the system
level: `horizontal_recursion`, `vertical_recursion`, `temporal_recursion`,
`resonance_feedback`, `cross_level_feedback`, `temporal_feedback`, `criticality_feedback`,
plus `event_processor`, `asynchronous_timing`, `multi_scale_thought`, `sparse_computation`,
`differential_processing`, `fast_operations`, `natural_shortcuts`, `stochastic_noise`,
`precision_control`, `combined_math`, `harmonic_calculator` and `fourier_processor`.

**Criticality is frozen.** `κ` is threaded through the mathematics everywhere — global
dynamics, event modulation, self-event probability, the `[1 + δ_crit(κ − κ₀)²]` feedback
gain. But `update_criticality` is defined three times (lines 4156, 6918, 9144) and called
**zero** times; `CyphaSystem.criticality` is set to `0.5` at line 1182 and thereafter only
read. Every κ-dependent term in v2 evaluates at its midpoint, permanently.

**The meta-learner never learns.** `param_adjustments = self.meta_model(...)` feeds a
hand-written `tanh(meta_loss)` scalar scaling, under the comment

```python
# Manual backward (no actual backward pass with autograd)
```
— `Cypha.py:2550`

so the meta-network's weights are never updated. There is no training loop anywhere in the
file.

Smaller signs of assembly-by-concatenation: `ResonatorLevel` is defined twice (lines 5435
and 6960), and `Level(Enum)` is defined and never referenced. `F.interpolate(...)` appears
63 times — shape coercion is the single most common operation in the file.

Resource bookkeeping is similarly inert: `ResourceOptimization.register_component` and
`WorkStealing.register_task` are never called, so the work-stealing loop is a permanent
no-op. And because 13 classes each construct a private `EnhancedResonance` actor (which in
turn constructs a private `FourierDomainProcessor`), a single `CyphaSystem()` would attempt
roughly 65–70 Ray actors against declared reservations summing to 6.4 GPUs.

The spine is eight solid edges (`mermaid:119-126`) chaining all ten layers, plus twelve

(`:1080-1085`); the resonance field `R` is a 100×100 complex density matrix initialised to

## What v2 adds to the mathematics

The Math Framework is a **strict superset of V1's `event-driven-math.md`** — V1's sections
reappear verbatim, down to punctuation, with only connective prose stripped and numbering
shifted. Five things are genuinely new.

**1. An input encoding layer.** V1 had none. v2 opens with a complex frame expansion
`E(x) = ∑ᵢ αᵢ(x)·e^{iθᵢ(x)}·φᵢ(x)` (`Math:11`), a mantissa/exponent precision scheme
`P(x) = B(x)·2^{E(x)}` (`:22`) and a piecewise overflow operator (`:30-35`).

**2. HLFC as a formal operator.** The name came from Cell AI v3 via V1, but v2 is the first
place it is written as a composition:

```
C(Ψ) = Fold(Map(Encode(Extract(Ψ))))
```
— `Math Framework.md:41`

with per-stage ratios ~50:1, ~20:1, ~50:1, ~100:1.

**3. The homomorphism bet.** This is the load-bearing architectural claim of v2:

```
Add(C(Ψ₁), C(Ψ₂)) = C(Ψ₁ + Ψ₂)
Scale(C(Ψ), α)    = C(α·Ψ)
Match(C(Ψ₁), C(Ψ₂)) = Similarity(Ψ₁, Ψ₂)
```
— `Math Framework.md:78-80`

If compression is a linear map admitting an inner-product-preserving matcher, the resonance
layer can work on compressed data and the system never decompresses. That is what licenses
the `CompOps --> Field` edge (`mermaid:120`).

**4. The resonance field gets its own equation** — the single biggest mathematical addition
in v2. V1 used `R_enhanced` as an undefined modulation factor; v2 gives `R` a
Liouville–von Neumann equation with a quadratic non-linearity and impulsive forcing:

```
∂R/∂t = −i[H,R] + γ(R² − R) + ∑ₑ δ(t − t_e)·F_event(R, E_e)
```
— `Math Framework.md:161`

The structure is worth reading carefully. `−i[H,R]` is anti-Hermitian-generated, hence
norm- and trace-preserving. `γ(R² − R)` has fixed points exactly at the idempotents
`R² = R` — the projectors — so it is a purification term driving the density matrix toward
a pure state, i.e. toward a decision. `Cypha.py:8202-8214` integrates it by forward Euler,
then re-Hermitises `R ← ½(R + R†)` and renormalises by `Tr R`, which is necessary because
the non-linear term is not trace-preserving.

Convolution is done spectrally, `O(N²) → O(N log N)`, and harmonics are table-driven with
`HARMONICS_SET = [1,2,3,5,7,11,13]` (primes) at just-intonation ratios (`Cypha.py:6997`,
`:8481-8497`).

**5. Logarithmic event scheduling**, `t_next = t_current·(1 + α·priority(E))⁻¹`
(`Math:150`), absent from V1's timing section.

The four-level hierarchy (§5) and everything downstream is inherited from V1 unchanged.

## Where the specification and the code disagree

v2 is the first era with code to check claims against — even unrunnable code answers
questions like "is this wired up at all?". Several claims do not survive. They are recorded
here because the archive will otherwise propagate them.

### "Capable of running on a single core"

Stated twice — `Cypha Architecture Explanation.md:7` and `:391` ("the entire system can run
efficiently on a single core"). The implementation shipped in the same directory is built
on Ray and CUDA: all 41 components are `@ray.remote` actors with `num_gpus=0.1..0.3`
defaulting to `device='cuda'`, and the module announces "Ray for distributed computing and
GPU acceleration" (`Cypha.py:6964`).

`grep -rl 'ray.remote' --include='*.py'` over the entire archive returns **only**
`cypha-v2/Cypha.py`. v2 is the one version that went distributed, and it did so while its
own document claimed the opposite. V1 had settled the single-core question a version
earlier (`cypha-v1/Cypha Convo Log.txt:1584`); v3 settles it again, permanently, by
dropping Ray, Torch and SciPy together.

### The compression layer is computed and thrown away

`CyphaSystem.process_input` runs the four compression stages and never uses their results:

```python
# 2. Compression
extracted_components = await self.fundamental_extraction.extract.remote(encoded)
symmetry_encoding    = await self.symmetry_encoding.detect_symmetries.remote(extracted_components)
crystal_mapping      = await self.crystal_mapping.compress.remote(encoded)
dna_folding          = await self.dna_folding.fold.remote(encoded)

# 3. Resonance Processing
await self.resonance_field.add_event.remote({'pattern': encoded, ...})
```
— `Cypha.py:1216-1230`

Two defects are visible at once. The resonance field is fed `encoded` — the **uncompressed**
tensor — so "Compressed data directly feeds the resonance field"
(`Architecture Explanation.md:375`) is not implemented. And the stages are applied *in
parallel to the same input* rather than composed: `crystal_mapping` and `dna_folding` both
take `encoded`, not their predecessor's output, so `C(Ψ) = Fold(Map(Encode(Extract(Ψ))))`
is specified but not built.

**v3 is the first version to actually compose them:**

```python
return self.df.fold(self.cl.map(self.se.encode(self.fe.extract(x))))
```
— `cypha-v3/Cypha.py:333`

### Other claims that do not hold

| Claim | Problem |
|---|---|
| "~500,000:1 practical compression" (`Arch:88`, `Math:39`) | inherited from Cell AI v3 about a different system; the four stage ratios multiply to 5,000,000:1, not 500,000:1; with v2's own defaults stage 1 maps 200 float32 to 150 float32 (~1.3:1); `DNAHierarchicalFolding._fold_1d` retains residuals *and* core data, so the output is not smaller than the input. Never measured. |
| "O(log n) for many operations" (`Arch:389`) | no operation is shown to be `O(log n)`. The one derived result is FFT convolution `O(N²)→O(N log N)`. "Logarithmic Scheduling" is a reciprocal scaling, not a logarithm. |
| Speedups of 1,000–10,000× / 100–1,000× / 10–100× (`Arch:385-387`) | copied from a V1 conversational table with no baseline, workload or measurement. v2 ships no benchmark; the first is `cypha-v4/benchmark_suite.py`. |
| Layer-10 multipliers "compound" — 100× × 2–4× × 5–10× × 3–5× (`Arch:333-357`) | the V1 source explicitly labelled the product a "theoretical maximum"; v2 drops the qualifier. |
| "Preserves complete numerical precision" at "~2-5% overhead" (`Arch:45`) | the implementation (`Cypha.py:7132-7175`) is a hand-rolled `frexp` storing mantissa and exponent in the **same** float32 dtype. Splitting a float into mantissa and exponent at equal precision adds no significand bits. The overhead figure is never measured. |
| The homomorphism identities (`Math:78-80`) | stated, never derived. `Extract` is a top-k truncation (non-linear), `Map` yields lattice-plus-defects, `Fold` is hierarchical — none obviously commutes with addition. There is no `CompOps` class in the code at all. |

## Dead ends

v2 is the high-water mark for machinery, and most of it is gone one version later.

| Dropped at v3 | Evidence |
|---|---|
| **Ray / distributed execution / GPU** | `ray.remote` matches only `cypha-v2/Cypha.py` in the whole archive |
| `WorkStealing` and idle-cycle precomputation | `work_steal` matches v2 alone |
| Just-in-Time Partial Decompression | specified, no class in the code, no successor |
| Mantissa/exponent precision + overflow as separate components | folded into `PrecisionController` in v3 (`cypha-v3/Cypha.py:1065`) |
| The ten-layer taxonomy itself | v3 organises around a flat component list with new concerns (`ModalityDetector`, `AnchorMemory`, `PhaseBridge`, `AdaptiveControlLoop`, `BinaryEncoder`); the layer numbering never returns |
| Crystal-lattice mapping | survives to v4 and vChatGPT, then gone; "HLFC" persists as a label only |

v2 also drops V1's entire "Core Enhancement Integration" set — adaptive thresholds, event
consolidation, event memory decay, event-triggered plasticity, emotional valence. None of
the seven enhancements diagrammed in `cypha-v1/enhanced-hrna.mermaid` survive into v2's
framework, and `valence`, `adaptive_threshold` and `plasticity` return essentially nothing
across later Python in the archive.

## How to read this era

v2 is where the project's ambition and its evidence diverge most sharply. The specification
is genuinely substantial — the density-matrix resonance field is real mathematics, and the
compressed-domain homomorphism is a coherent (if unproven) architectural bet. But the
document asserts single-core operation while the code requires a GPU cluster, asserts
compressed-domain processing while the code discards the compressed data, and inherits
compression and speedup figures from a system that is not in the archive.

Everything after v2 is, in part, a reaction to this. v3 deletes the frameworks, composes
the compression it was given, and shrinks the code by 71%.
