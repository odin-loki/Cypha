### 1.2 The real blocker: native crash in cell sweep variant H15

```
[cell_sweep] variant H14 (17/25)
[cell_sweep] variant H15 (18/25)
PS>TerminatingError(): "overnight run failed exit=-1073741819"
```
— `bench/results/production_overnight_20260628_170701.log:647-649`

`-1073741819` = `0xC0000005` = **Windows ACCESS_VIOLATION**. This is a native crash inside `cypha_cell_hypothesis_sweep.exe`, not a scripting bug. It happened **after 300k-scale training started for variant H15** ("AXIOM-evolved cell") — the previous 22 fast/medium-tier smoke runs (n_train ∈ {80, 200}) never hit it, so the fault is scale-dependent (300k steps) or state-dependent (something left over from H01–H14 that only corrupts memory far enough into H15's run).

**H15 config** (`native/src/cyphalm/cypha_cell_hypothesis.cpp:136-138`):
```cpp
} else if (id == "H15") {
    cfg.use_axiom_activation = true;
    cfg.alpha_learnable = true;
```

**Gate evaluation path** (`native/src/cyphalm/char_lstm.cpp:121-135`, `native/include/cypha/cyphalm/axiom_activation.hpp:21-31`): per-dimension enum-dispatch to `sigmoid`/`tanh`/`eml_nand`, size-guarded (`axiom_grammar_.i_gate.size() == hidden`). Nothing in this path is obviously unsafe (no recursion, no unchecked indices, fixed-size vectors set once at construction) — which suggests the corruption most likely originates **elsewhere** (e.g. state carried over from a prior variant's destructor/reset, a shared buffer sized for a different `hidden`/`n_experts` combination, or heap corruption from an earlier variant that only crashes when H15 touches the corrupted region). **This needs a targeted repro, not a guess** — see the plan below.

### 1.6 Resolution (2026-07-11)

**Repro.** Added the ability to run a single cell-sweep variant directly (`cypha_cell_hypothesis_sweep --cell-variant H15 --n-train N ...`, which already existed as a flag but wasn't being used standalone for repro). H15 alone:
- `n_train=2000`, `n_train=50000`: exits 0, finite BPC, no crash.
- `n_train=300000`: **crashed deterministically**, single-variant, no other variants involved — i.e. **scale-dependent, not order-dependent**. Ruled out "state left over from H01–H14" as the mechanism.

**Root cause.** Built a `RelWithDebInfo` (`-O2 -g`) config of `native/build_math` (plain `Debug`/`-O0` hit an unrelated MinGW linker bug — duplicate RTTI symbols — so used `RelWithDebInfo` instead) and ran the isolated H15@300k repro under GDB. Faulting frame: `cypha::intelligence::compute_calibration` (`native/src/intelligence/measurers.cpp:216`), an out-of-bounds write to `bin_count`/`bin_conf`/`bin_acc`. Chain:

1. `char_lstm.cpp`'s `backward_step` had **no dedicated gradient path for axiom-activated gates** — when `cache.used_axiom` is true (H15's per-dimension `AxiomGateGrammar` mixing `Sigmoid`/`Tanh`/`Eml`), the code fell through to the plain-sigmoid gradient formula for every gate regardless of which activation the forward pass actually used for that dimension. This is a real correctness bug (wrong gradients for `Tanh`- and `Eml`-selected dimensions), and after tens of thousands of training steps at 300k scale it was enough to send LSTM weights numerically unstable.
2. Divergent weights → `log_probs` in `lm_intelligence_monitor.cpp`'s `max_log_prob_confidence` became NaN.
3. `max_log_prob_confidence` passed that NaN through `std::clamp(x, 0.0, 1.0)` — **`std::clamp` does not clamp NaN** (all three comparisons it does internally are false, so it returns the NaN operand unchanged) — so a NaN `confidence` reached `compute_calibration`.
4. `compute_calibration` cast that NaN confidence to `int` for a bin index. On x86-64, casting a NaN double to `int` yields `INT_MIN` (an "indefinite integer"), not 0. The existing bounds check was upper-bound-only (`if (idx >= bins) idx = bins - 1;`), so `INT_MIN` sailed straight through into `bin_count[idx]`/`bin_conf[idx]`/`bin_acc[idx]` — an out-of-bounds write far outside the vector, i.e. the `ACCESS_VIOLATION`.

**Fix (root cause, not a workaround):**
- `native/src/cyphalm/char_lstm.cpp`: added a real per-dimension axiom-gradient dispatch (`axiom_gate_grad`, mirroring the existing pure-EML dispatch convention) so `Sigmoid`/`Tanh`/`Eml`-selected gate dimensions each get their correct derivative instead of always using the sigmoid formula.
- `native/src/cyphalm/lm_intelligence_monitor.cpp` + `native/src/intelligence/measurers.cpp`: hardened against non-finite confidences regardless of where they originate — `max_log_prob_confidence` now explicitly checks `std::isfinite` before clamping (falls back to a neutral 0.5), and `compute_calibration` skips non-finite confidences and clamps `idx` on both ends (not just the upper bound). This is a genuine memory-safety fix independent of the gradient bug above — `std::clamp`'s NaN passthrough plus an upper-bound-only index check was always exploitable by any future source of NaN, not just this one.

**Verified:** re-ran the isolated H15@300k repro against the fixed build — **exit 0, no crash** (previously `-1073741819`/`0xC0000005`). H15's `bpc`/`kappa` come back `null` (NaN) at 300k even post-fix — the AXIOM-evolved cell still numerically diverges under this evolved gate grammar at production scale (confirmed separately: finite BPC at `n_train` 2,000 and 50,000, `null` only at 300,000) — but this is now a **handled, non-fatal outcome** (recorded as a normal result row with a null metric, same as any other numerically-unstable configuration) rather than a process crash. Untangling *why* H15 diverges at 300k is a separate numerical-stability research question for the AXIOM cell itself (candidate follow-ups: gradient clipping, lower LR for `alpha_learnable`, or fitness-reselecting the grammar with a stability penalty) and out of scope for this crash-fix pass.

**Sweep runner hardened regardless of root cause.** `cypha_cell_hypothesis_sweep.cpp` now runs each `--overnight-sweep`/`--overnight-sweep-smoke` variant in its own child process (re-invoking itself with `--cell-variant <id>`, via the existing `cypha::bench::run_executable_capture` helper already used elsewhere in the bench tooling) instead of one long-lived in-process loop. A variant that crashes is caught by its parent, recorded in a new `"failed"` array (id/tier/exit_code/error) in both the sweep's JSON output and the on-disk manifest, and the sweep continues to the next variant. `--cell-variant` invocations (including the isolated children themselves) still run in-process, so there's no recursive re-isolation and no change to that CLI's existing behavior/flags. Verified with a temporary `CYPHA_SWEEP_FORCE_CRASH_VARIANT` env hook (test-only, forces `std::abort()` for a named variant): a smoke sweep with `CYPHA_SWEEP_FORCE_CRASH_VARIANT=H06` showed H06 recorded in `"failed"` (`exit_code=-1073740791`) while the other variants that ran in the same smoke tier (`B2`, `H14`) both completed with valid results and the parent process still exited 0.

**CTest verification:** `ctest --test-dir native/build_math -R "cell_hypothesis|d19|d20|d56|d57"` — **6/6 passed**, including `native_cell_hypothesis_overnight_smoke` which runs `--overnight-sweep-smoke` (all 25 variants, smoke scale) end-to-end with the new isolation path active. A pre-existing, unrelated failure in `native_ewc_hybrid_smoke` (`std::length_error: cannot create std::vector larger than max_size()`) was confirmed via `git stash` A/B testing to reproduce identically on the pre-fix source tree — **not caused or regressed by this work**, left untouched/out of scope.

**D21 stdout anomaly — real bug, fixed.** The `$env:CYPHA_OVERNIGHT_MATH_INTEGRATION` hypothesis was checked directly and ruled out: `cyphalm_bench_native.exe`/`cypha_cell_hypothesis_sweep.exe` never call `getenv` on that variable at all (only used by *other* PowerShell scripts and by `bench_domains.cpp`'s meta self-checks that just grep script text for the string), and splatting an extra unrecognized `-MathIntegration` switch parameter onto `run_rpsm_overnight.ps1` (which never declared that param) is a silent no-op in PowerShell, not an error — confirmed empirically both ways. The actual structural cause: `run_d17_overnight.ps1` invokes its native binary through `Invoke-NativeWithProgressLog`, which merges `2>&1` and pipes through `Tee-Object` — routing output through the PowerShell pipeline, which `Start-Transcript` reliably captures. `run_rpsm_overnight.ps1` instead called `& $exe ...` **bare, with no piping**, so its stdout went straight to the inherited console handle; when invoked several `&`-levels deep (`run_production_overnight.ps1` → `run_overnight_all.ps1` → `run_rpsm_overnight.ps1`) under `Start-Transcript`, that raw native-process stdout was silently dropped from the transcript (this is a known Windows PowerShell 5.1 Transcript limitation for un-piped native command output). Fixed by giving `run_rpsm_overnight.ps1` the same `2>&1 | Tee-Object -FilePath <dedicated log>` treatment as `run_d17_overnight.ps1` already uses (plus a temporarily relaxed `$ErrorActionPreference` for the duration of the call, matching the same pattern) — verified with a standalone `-Fast` run: the BPC JSON now appears in both the console output and a new `bench/results/overnight_d21_<timestamp>.log` file.

## 4. Plan for today (2026-07-11)

Ordered so each step unblocks the next; stop and reassess after any red flag.

1. **Commit the stderr fix** already sitting uncommitted in `scripts/run_d17_overnight.ps1` (it demonstrably helped — got 18/25 variants further than without it). Low risk, no reason to keep it uncommitted.
2. **Reproduce the H15 crash in isolation** — run `cypha_cell_hypothesis_sweep --overnight-sweep --profile d17 --n-train 300000` filtered to just variants H14→H16 (or however the tool supports a subset) to confirm it's H15-specific and scale-triggered, not order-dependent state corruption from H01-H14. If a `--variant` / `--only` flag doesn't exist on the sweep tool, add one — it's useful for exactly this kind of bisection going forward.
3. **Root-cause the access violation** — likely candidates to check first, in order of suspicion:
   - Memory/state not reset between variants in `cypha_cell_hypothesis_sweep.cpp` (look for reused buffers sized for a previous variant's `hidden`/`n_experts`/`n_train` config)
   - `AddressSanitizer` or `/fsanitize=address` build of `cypha_cell_hypothesis_sweep` + a small-n_train repro of H15 alone, to catch heap corruption before it manifests as a crash 18 variants later
   - Confirm the `axiom_grammar_` size guard (`char_lstm.cpp:123`) never silently falls through when `hidden` mismatches (guard exists but check what happens on the `else` — does it fall to EML/sigmoid silently, and would *that* explain divergent numerics rather than the crash itself?)
4. **Harden the sweep runner** regardless of root cause: isolate each variant in its own subprocess (or at least wrap in a structured-exception/signal handler on Windows) so **one variant's crash doesn't discard the other 24 variants' worth of already-completed work**. This is the single highest-leverage fix — it turns "lose an entire overnight run to one bad variant" into "lose 45 minutes and get 24/25 results anyway."
5. **Re-run the production overnight** (`scripts/run_production_overnight.ps1 -BuildDir native/build_math -MathIntegration`) once 1 and 4 are in, in a **Cursor-managed terminal** (not an external `Start-Process` window — this has caused visibility confusion in prior sessions).
6. **Verify the D21 stdout anomaly** (§1.4) independently — run `scripts/run_rpsm_overnight.ps1 -Production` alone and confirm BPC JSON prints before trusting the next full pipeline run.
7. **On completion:** run `finalize_production_overnight.ps1` → `commit_production_lock.ps1 -Force` to land the refreshed lock (D17 math-integration BPC/κ @ 300k, D21, and a real 28-variant — or however many survive — cell sweep).
8. **If time remains:** start scoping P1 (hidden-dim scale experiment) — read `cypha_self_correcting_paper4.md:671-769` in full for the exact Phase 1-5 implementation roadmap it lays out, and check what `--hidden-dim` / config plumbing already exists vs. needs adding.
