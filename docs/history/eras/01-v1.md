## Three architectures, two rejected

This era's value is that it records the rejections.

**IRENA** — "Integrated Recursive Event-Driven Neural Architecture" (`:55`) — is the first
fusion of the three prototype threads, extending the Brain Model's state to
`Ψ(t) = {C,A,M,O,G,F,N,R}` (`:75`). It and its revision IRENA 2.0 are killed by the author:

> I think we need a new architecture... we are not achieving the full reuse of the math's
> that we could be achieving.
> — `:734`

**HAEDF** — "Harmonic Asynchronous Event-Driven Framework" (`:821-822`) — proposes putting
the event machinery in a *separate computational layer beneath* the architecture. Rejected
twice, the second time bluntly:

> I dont like anything you have done with event driven. The old architecture was better.
> — `:831`

The lesson enforced here produces the era's central document: **the event machinery must
live inside the mathematics, not in a runtime layer beside it.** That is what
`event-driven-math.md` is.

**HRNA** — Harmonic Recursive Neural Architecture — is what survives. Its defining
structural move is replacing the Brain Model's *cellular* level with a **resonator** level
operating in the frequency domain (`:769`, `:782`). That single substitution is what makes
the stack harmonic rather than neuronal, and it is what the H in HRNA stands for.

## The mathematics

The master equation makes events Dirac impulses on the right-hand side of the state ODE:

```
dΨ/dt = F_continuous(Ψ, t) + ∑ₑ F_event(Ψ, E_e, t)·δ(t − t_e)
```
— `event-driven-math.md:11`

The log states the contrast with the prototypes directly:

> Original systems: Events were conceptual or implementation details
> New system: Events are fundamental mathematical entities with Dirac delta functions.
> — `Cypha Convo Log.txt:1145-1146`

Event generation is a sum of four indicator-function generators (`:26`):

```
E(Ψ,t) = ∑ᵢ δ(t−tᵢ)[G_pattern + G_surprise + G_resonance + G_external]
    G_pattern   = [R(Ψ,pattern) > θ_pattern]
    G_surprise  = [‖Ψ − Ψ̂‖ > θ_surprise]
    G_resonance = [R_enhanced(Ψ) > θ_resonance]
    G_external  = A(t)
```

Every level of the hierarchy then takes the same shape — *inherited term plus impulse sum*:

| Level | Equation (`event-driven-math.md`) |
|---|---|
| Resonator | `dRᵢ/dt = ωᵢRᵢ + ∑[W_ij σ(R_j)] + Dᵢ∇²Rᵢ + Qᵢ(Rᵢ)·R_enhanced(Rᵢ) + ∑ₑ E_e δ` (`:74`) |
| Wave/field | `∂C/∂t = D∇²C + f(C) − γC + ∑ₑ I(e,x,t) δ` |
| Assembly | `dA_k/dt = F_k(A_k) + ∑[V_ki σ(Rᵢ)] − φ_k∑[C_kl A_l] + T_k(G,A_k)·R_enhanced + ∑ₑ E_e δ` (`:88`) |
| Oscillator | `do_k/dt = [0,−ω_k; ω_k,0]o_k − γ_k o_k + H_k(a_k) + ∑[K_kl o_l] + ∑ₑ E_e δ` |
| Module | `dM_s/dt = −M_s + F_s(M_s) − α∑[C_ss′ M_s′] + G_s(O,G) + N_s(M_s)·R_enhanced + ∑ₑ E_e δ` (`:106`) |
| Global | `dG/dt = −α_G G + W_G[M;O] + R_G(G) + P_G(Ĝ(t+Δt│t)) + κ(t)R_critical(G) + ∑ₑ E_e δ` (`:124`) |
| Criticality | `dκ/dt = α(│∇Ψ│² − κ₀) + β·R_crit(f,κ) + ∑ₑ E_crit δ` (`:128`) |

Criticality is promoted to a first-class dynamical variable with its own event-driven ODE,
coupled back into both global dynamics and event modulation.

Three orthogonal recursion axes — horizontal (within-level, `:190`), vertical
(between-level, `:194`) and temporal (predictive, `:198`) — are all made event-sensitive by
one syntactic device, a multiplicative gain:

```
ψᵢ(t+Δt) = f_ψᵢ(·) × [1 + α·R(·)] × [1 + β_E·∑ₑ E_e(t)δ(t−t_e)]
```

Feedback is **resonance-amplified**: loop gain scales as `[1 + γ_res·R_enhanced(ψᵢ)]`
(`:146`), so feedback is strongest exactly where the system is already resonating. The
criticality feedback term `F_crit(ψ,κ) = F_base(ψ)×[1 + δ_crit(κ(t) − κ₀)²]` (`:177`) is
worth noting: the quadratic amplifies feedback *away* from optimal criticality, not at it.

Asynchrony is per-component — `dtᵢ = f(priority(ψᵢ), complexity(ψᵢ), resources(t))` (`:56`)
with a load-dependent transmission delay (`:58`). Time becomes a per-node quantity rather
than a global loop index.

"Thought" is formalised as event cascade (`:221`), self-generated stream (`:265`) and
resonant chain strength `C_resonant(E₁..Eₙ) = ∏ᵢ R_enhanced(Eᵢ) × ∏ᵢⱼ Coupling(Eᵢ,Eⱼ)`
(`:276`), with sparsity as an explicit indicator `[‖Δψᵢ‖ > θ_change(t)]` (`:290`).

## The seven enhancements

`enhanced-hrna.mermaid` is not the architecture diagram; it is the diagram for seven
accepted enhancements out of fifteen brainstormed (`:1195-1285`). The selection is recorded
verbatim: **"Do All except attention spotlight"** (`:1386`) — and the attention-spotlight
formula proposed at `:1290` is correspondingly absent from the diagram.

| Enhancement | Formula (`enhanced-hrna.mermaid:17-23`) |
|---|---|
| Adaptive thresholds | `θ_adaptive(t) = θ_base×[1 − α_context·relevance − β_history·novelty]` |
| Event consolidation | `E_consolidated = consolidate({E_similar}, similarity_threshold)` |
| Event memory decay | `M_event(t) = ∑ᵢ Eᵢ(tᵢ)exp(−(t−tᵢ)/τᵢ)` |
| Event-triggered plasticity | `dW_ij/dt = η·Eᵢ·Eⱼ·f(timing)·priority(Eᵢ)·priority(Eⱼ)` |
| Stochastic resonance | `R_noisy(ω,ψ) = R_enhanced(ω,ψ) + η(t)` |
| Predictive generation | `E_predictive(t) = P(E│ψ̂(t+Δt))·δ(t − t_predict)` |
| Emotional valence | `priority_emotional(E) = priority_base(E)×[1 + α_emotion·valence(E)]` |

The plasticity rule is learning on *event co-occurrence* rather than activation
co-occurrence — glossed in the log as "events that fire together, wire together" (`:1330`).

## The pivot that shaped everything after

Asked about hardware, the dialogue produces a cluster specification: 64–256 CPU cores,
4–8 A100/H100 GPUs, 128 GB–1 TB RAM, InfiniBand, a **$1M–$10M** budget (`:1505-1580`).

The next human turn discards it in one sentence:

> Is there anyway we can get this running back on a single core?
> — `:1584`

What follows is a ten-item single-core optimisation programme (`:1611-1645`) and a minimal
viable configuration of 16 resonators on commodity hardware (`:1647-1653`). The ten
shortcuts are: harmonic scaling `R_enhanced(ω,Ψ) ≈ R_direct(ω₀,Ψ)×H(ω/ω₀)`; logarithmic
event scheduling; partial unpacking of compressed states; phase-only Kuramoto oscillators
`dθ_k/dt = ω_k + ∑ⱼK_kj sin(θⱼ − θ_k)`; separation of variables; impact-threshold pruning;
block-sparse mat-vec; logarithmic memory binning; recursive decay; and modal decomposition
`Ψ(x,t) = ∑ᵢAᵢ(t)φᵢ(x)`.

`Cypha Speed Improvements.txt` is a verbatim excerpt of that passage, saved separately —
the author thought it worth keeping on its own.

**Every later Cypha version inherits this constraint.** The distributed/cluster path is
never revisited; the eventual native C++ product is single-machine, CPU-first, and its
CHANGELOG records CUDA CI jobs being removed rather than added.

Session 2 also introduces a fourth source system, **Signal AI** (`:1869-1875`),
contributing a complex-valued universal encoder `E(x) = ∑ᵢ αᵢ(x)e^{iθᵢ(x)}φᵢ(x)` and a
commutator resonance field `∂R/∂t = −i[H,R] + γ(R² − R)`, plus a precision-preservation
scheme `P(x) = B(x)×2^{E(x)}` with an overflow guard — written in response to
"add an overflow catcher so no precision is lost... Ive seen it before" (`:2440`).

### A methodological dead end

The era also abandons its own way of arguing. Compounded speedup products —
"≈ 325,000×" (`:2082`) and "10¹⁶–10²¹× theoretical" (`:2348`) — are presented and then
quietly walked back to "1,000-10,000× for simple patterns" in the same documents. The
multiplicative-stacking style of claim inherited from the prototypes does not survive V1
intact, and does not appear at all once real benchmarks arrive in v4.

### An unreconciled inconsistency

Logarithmic event scheduling is written as `t_next = t_current×(1 + α·priority(E))` at
`:1614` but with the factor inverted, `(1 + α·priority(E))⁻¹`, at `:2036` and `:2232`. The
two forms schedule high-priority events *later* and *sooner* respectively. The archive
never reconciles them.

## What reached the native product

- **Single-core, commodity-hardware execution as a hard constraint**, decided at `:1584`.
  This is the most consequential line in the entire archive.
- **Sparse, threshold-gated updates** — `[‖Δψᵢ‖ > θ_change(t)]`.
- **Precision preservation and overflow guarding** as a standing concern, which reappears in
  the native code's careful float32/float64 discipline (see
  [`native/include/cypha/nig_field.hpp`](../../../native/include/cypha/nig_field.hpp),
  "per-element float64 sum then float32 round").

The resonator/oscillator/criticality mathematics itself does **not** survive. It defines
family A, which ends at v7.
